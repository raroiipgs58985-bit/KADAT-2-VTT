# Local Combat v0.2 — accepted Core adapter

Изолированный браузерный эксперимент. База: принятый Combat Core
`e98837b92abc74ac501b52c5f2ea2e79b86f96b3`. Production-код не изменяется.

Восстановлены профили двух персонажей из канонических диапазонов с примечаниями,
начальные раны 26/32 и 33/33, отдельное runtime-состояние, дробные координаты,
ручная очередь, выбор цели и персонального оружия, журнал, экспорт и сброс.
Карта и начальное расположение — тестовая расстановка; drag не списывает ОД.
Профиль Пака назван по прямому решению пользователя, ячейка имени пуста.
Файл `fixture.json` восстановлен из таблиц: это не побайтовая копия утраченного JSON.
Полный снимок прочитанных диапазонов — `canonical-profiles.json`.

Восстановленный интерфейс сохранён checkpoint-коммитом `e306497` и отправлен
в новую экспериментальную ветку. Поверх него подключён принятый Combat Core.
Работают настоящий одиночный выстрел, последствия, журнал вычислений и replay.
Двусторонний сценарий «попадание Келуса / промах Пака» полностью разрешается
Core и воспроизводится из журнала. Сценарий с двумя попаданиями пока BLOCKED:
порядок потери ОБ от Цепного требует ответа автора. Попадание Пака сохраняется.

Подробная карта API, источников, поддержанных свойств и открытых границ —
[REPORT.md](REPORT.md). Неподтверждённые операции не объявляются выполненными.

## Запуск

Из корня репозитория:

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm --dir experiments/local-combat dev
```

Телефон в той же сети: `http://<IP компьютера>:5173`; в облачной среде нужен
доступный preview/port-forwarding URL. Открытие через `file://` не поддерживается.
Vite используется из уже существующей установки клиента, новых зависимостей нет.

```sh
corepack pnpm --dir experiments/local-combat test
corepack pnpm --dir experiments/local-combat typecheck
corepack pnpm --dir experiments/local-combat build
```

Никаких Supabase, авторизации, БД или серверной боевой логики.

## Использование

- «Сценарий: попадание / промах»: Пак устанавливается в 0.75 м от Келуса **до**
  боевых действий; затем выстрел Келуса, штатная передача хода и проверка
  атаки Пака с d100=90. Итог: Келус 26/32, Пак 31/33, блок 249/250.
- «Сценарий: два попадания» использует d100=25 Пака и сохраняет зависимую
  от порядка потери ОБ операцию как pending. Это отдельная незакрытая проверка.
- На обычной начальной карте первый выстрел использует `100:45,10:2,100:20`.
  Урон 2 с учётом Керамита Пака, Пак 31/33, блок 249/250. Вторичная ВН=20
  проходит через C-2. Это реальный результат Core, не demo-ответ.
- «Продолжить pending» принимает только оставшиеся кубики: если d100 уже
  сохранён, вводите следующий куб урона, например `10:2`.
- При неизвестном правиле одних кубиков недостаточно: операция остаётся pending.
- Экспорт содержит структурированный журнал и replay-команды с фактическими
  бросками. «Открыть replay» воспроизводит их с проверкой версии и решений автора.
- Отмена разрешена только если ни одного кубика ещё не брошено. Полный сброс
  всегда создаёт новую тестовую сессию из неизменяемого профиля.
- Начальную очередь можно выбрать до первого действия. Далее «Передать ход»
  использует accepted session/action APIs; дополнительных бесплатных атак нет.

Для мобильного Chromium smoke test при работающем Vite:

```sh
chromium --headless --no-sandbox --disable-dev-shm-usage \
  --remote-debugging-port=9222 --user-data-dir=/tmp/kadat-v02-browser about:blank
node experiments/local-combat/scripts/browser-smoke.mjs
```
