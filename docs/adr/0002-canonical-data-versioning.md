# 0002 — Canonical Data Versioning Architecture

## Status

Accepted — решение пользователя в Phase 2.1.

## Context

KADAT 2 требует обновляемых источников правил без разрушения существующих
кампаний и объектов. Канонические Excel-таблицы могут менять параметры,
свойства и механику, а конкретные экземпляры могут иметь индивидуальные
изменения. Автоматическая подмена их основы актуальным каноном нарушила бы
сохранность состояния и прежнего поведения.

## Decision

- **Immutable canonical releases:** опубликованные канонические выпуски
  неизменяемы; изменения создают новые версии совместимых наборов данных.
- **Template/Instance separation:** официальная запись канона отделена от
  конкретного объекта. Instance сохраняет происхождение, версию шаблона,
  индивидуальные изменения и состояние. Instance Override Layer не
  превращает уникальный объект в отдельный канонический шаблон.
- **Versioned campaigns:** кампании имеют версии и закреплённый Canonical
  Release; обновление канона не переключает активную кампанию.
- **Provenance tracking:** производные данные сохраняют связь с источником,
  его версией, происхождением записи и причиной изменения; преобразование
  должно быть воспроизводимым.
- **Controlled migration:** технические, канонические и индивидуальные
  переходы контролируются; конфликты требуют решения. Старые определения
  не удаляются автоматически.
- **No automatic runtime updates from canonical changes:** изменения канона
  не обновляют существующие экземпляры и правила кампаний автоматически.
  Excel не является runtime источником.

Принятая альтернатива прямому использованию изменяемого канона — работа с
проверенными закреплёнными выпусками. Это сохраняет возможность обновления
источников при контролируемом применении изменений к игре.

Подробности: [канонические данные](../canonical-data.md) и
[версионирование](../versioning.md). Решение не выбирает БД, ORM, API,
формат JSON или схемы реализации.

## Consequences

Положительные последствия:

- сохраняются данные старых кампаний и связь с использованными правилами;
- уникальные предметы не ломаются из-за автоматической подмены шаблона;
- изменения можно проследить и применить контролируемо.

Издержки:

- потребуется система миграций и проверка совместимости;
- потребуется больше метаданных и сохранение исторических определений.

Сроки поддержки исполнения старых правил остаются открытым вопросом.
Принятие архитектуры не означает реализацию импорта, Rules Engine или
игровых систем на этом этапе.
