# 0003 — Client game layer and Rules Engine source bundling

## Status

Proposed — предложение агента в Phase 3A-1. Не утверждено пользователем.

## Context

Рабочий прототип боя находился в `experiments/local-combat` вне production
workspace и импортировал Rules Engine по относительному пути к исходникам.
Для настоящего клиента нужно было подключить Core и перенести адаптер
(профили, команды атаки, перемещение, replay) без изменения правил и без
новых внешних зависимостей. Сервер боя и многопользовательский режим
в эту фазу не входят.

## Decision

- Адаптер переносится в `apps/client/src/game` — слой без React, браузерных
  API (кроме источника случайных бросков, передаваемого явно) и сетевого
  кода. React-компоненты в `apps/client/src/ui` только вызывают его команды.
- `@kadat/rules-engine` и `@kadat/contracts` объявлены зависимостями клиента
  (`workspace:*`); Vite и TypeScript разрешают их в исходники `src/index.ts`
  через alias/paths. Клиент и его тесты не зависят от устаревшего `dist/`
  и порядка сборки пакетов.
- Эксперимент остаётся неизменной точкой отсчёта со своими тестами.

## Alternatives

- Отдельный пакет `packages/combat-session` сейчас — правильнее для будущего
  сервера, но это новая граница пакетов до появления второго потребителя.
- Импорт собранного `dist/` — требует сборки Rules Engine перед dev/test
  клиента и усложняет локальную работу.

## Consequences

- Адаптер пока существует в двух копиях: в эксперименте (заморожен) и в
  клиенте (развивается). Новые изменения вносятся только в клиент.
- Когда появится авторитетный сервер боя, `src/game` выносится в общий пакет,
  которым будут пользоваться сервер (исполнение команд) и клиент
  (предпросмотр). Ядро правил при этом не меняется.
