# ADR 0005: Снимок «Арсенала» и воспроизводимая загрузка

Статус: Accepted (решение автора 23.11.2026: «Оружие персонажа — через Арсенал»;
принцип — ADR 0002).

## Контекст

Боевой VTT должен брать оружие и броню из «Арсенала Кадата». Программа не читает
Google-таблицы во время игры (ADR 0002: таблица — источник, а не runtime).

## Решение

- Пакет `packages/canonical-data`.
- `sources/arsenal-2026-11-23.json` — снимок значений ячеек листов оружия, брони,
  силовых полей и свойств из файла `Арсенал Кадата.xlsx` (SHA-256 исходного файла
  и способ извлечения записаны в снимке; картинки не переносятся).
- `src/arsenal.ts` — чистый разбор снимка: столбцы ищутся по заголовкам, каждая
  запись хранит лист и строку источника, нераспознанное попадает в `issues`,
  значения не додумываются.
- `dataset/arsenal.json` — проверенный набор данных; тест требует, чтобы сборка
  из снимка давала ровно его (воспроизводимость).
- Новая версия таблицы → новый снимок с датой → пересборка → отчёт о различиях.
- `sources/profiles-lists-2026-11-24.json` — снимок листов «Навыки», «Таланты
  (обновлены)» и старого листа «Таланты» из «Профилей персонажей». Таблицы —
  первоисточник (решение автора 24.11.2026); старый лист даёт только таланты,
  которых нет в обновлённом (помечены `legacy`).

## Последствия

- Игра не зависит от доступа к Google и от изменений таблицы во время сессии.
- Отчёт `issues` показывает автору ошибки и пробелы таблицы (неописанные свойства,
  опечатки, ячейки, испорченные Excel).
- Механика свойств оружия реализуется в ядре отдельно; набор данных хранит
  только их названия и параметры.
