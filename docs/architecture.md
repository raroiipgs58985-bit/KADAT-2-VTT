# Предварительная архитектура KADAT 2

KADAT 2 — браузерная VTT-платформа с собственной системой правил. Ниже
зафиксировано утверждённое пользователем направление Phase 0.1. Отдельные
технические детали могут изменяться по мере уточнения требований; такие
решения должны быть документированы. Предложения и кандидаты не считаются
утверждёнными решениями.

## Направление разработки

| Область    | Направление                         | Статус                                                                    |
| ---------- | ----------------------------------- | ------------------------------------------------------------------------- |
| Frontend   | React + TypeScript + Vite           | Утверждённое направление; технический bootstrap создан в Phase 1.0        |
| Backend    | Node.js LTS + Fastify               | Утверждённое направление; bootstrap и health endpoint созданы в Phase 1.0 |
| Realtime   | WebSocket layer                     | Кандидат; библиотека и протокол сообщений не выбраны                      |
| Core       | Independent TypeScript Rules Engine | Создан пустой пакет; игровых правил нет                                   |
| Repository | pnpm workspace                      | Минимальный workspace настроен в Phase 1.0                                |

## Границы системы

- **Client** отвечает за интерфейс и взаимодействие пользователя с платформой.
  Интерфейс не определяет игровые правила.
- **Server** отвечает за серверные операции и будущие многопользовательские
  сессии. Серверный framework не должен определять механику KADAT.
- **Rules Engine** в дальнейшем реализует только утверждённые правила KADAT.
  Ядро должно быть независимо от интерфейса, React, Fastify и транспорта
  сообщений. Client и Server могут обращаться к ядру через явно определённые
  границы; ядро не должно зависеть от этих приложений.

Источники механики и порядок разрешения конфликтов описаны в
[rules-sources.md](rules-sources.md). Замена механики правилами других систем
не допускается.

## Состояние Phase 1.0

Создан только технический каркас утверждённого направления:

- `apps/client` — стартовая страница React и Vite entry point;
- `apps/server` — запуск Fastify и `GET /health`;
- `packages/contracts` — пустой TypeScript модуль без игровых контрактов;
- `packages/rules-engine` — пустой TypeScript модуль без игровой механики.

Общие пакеты собираются независимо, не имеют runtime зависимостей и не
подключены к приложениям до появления реальной необходимости. В каркасе
используется ESM; общие пакеты собираются в JavaScript и объявления типов.
ESM утверждён пользователем как постоянный основной формат модулей KADAT 2.
Node packages используют ESM/NodeNext в соответствии с runtime, frontend —
ESM через Vite. Совместимость с CommonJS сейчас не требуется; dual
ESM/CommonJS не поддерживается. Решение зафиксировано в
[ADR 0001](adr/0001-esm-module-format.md).

Настроены TypeScript strict, ESLint, Prettier и Vitest. Есть технический тест
health endpoint. Для остальных пакетов отсутствие тестов пока допускается
явно; Playwright отложен до появления браузерного функционала.

Realtime не реализован. Renderer и база данных не выбраны. Игровые подсистемы,
аутентификация, deployment инфраструктура и CI отсутствуют. Конкретная
реализация realtime и постоянные межпакетные API остаются открытыми.

Версии окружения, команды и установка описаны в [README](../README.md).
Изменения архитектурных решений документируются; назначение
[ADR](adr/README.md) сохраняется; принятое решение о формате модулей
зафиксировано в ADR 0001.

Принципы работы с каноническими данными описаны в
[canonical-data.md](canonical-data.md), система версий и миграций — в
[versioning.md](versioning.md). Решение Phase 2.1 закреплено в
[ADR 0002](adr/0002-canonical-data-versioning.md).

Фактическое расширение общих пакетов описано в
[Infantry Rules Kernel — Phase 2.2A](infantry-combat-kernel.md) и
[Infantry Ranged Actions — Phase 2.2B-1](infantry-ranged-actions.md).
Стек и границы Client / Server / Rules Engine сохранены.
